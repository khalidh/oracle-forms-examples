## Local APEX Administration

The local `ADMIN` instance account was reset in the `ORACLE_FORMS_EXAMPLES` PDB with the APEX 24.2 `apxchpwd.sql` script. The script generated a random password and stored local connection details in repository-root `.env.apex`; that file is ignored by Git and ACL-restricted. Never print it, commit it, or copy its password into chat. The checked-in `.env.apex.example` contains names and URLs only.

The historical demo workspace `QAFE_FORMS_DEMO` is provisioned against the old `STUDENT` schema. Its `QAFE_DEMO_BUILDER` account remains unverified; a read-only check on 2026-10-19 found its Team Development flag enabled, contrary to the intended App Builder-only profile. No application was created in that old workspace.

The clean preview uses `QAFE_FORMS_CLEAN` / `QAFE_FORMS_BUILDER` on PDB `QAFE_CLEAN`. The page requires authentication and exposes no form or DML process. Its local example data is limited to course rows 454, 455, and 456; this is not production authorization.

Pages 7 and 9 display the owner-approved imported rows without assuming their historical `CREATED_BY` matches the current APEX user. Pages 8 and 10 update/delete by primary key while retaining Builder authorization, row-count checks, validation triggers, and child-record deletion guards.
