## Local Preview Operational Notes

These steps describe only the loopback `QAFE_CLEAN` preview. They are not a production backup, deployment, or disaster-recovery plan; production target, retention, RPO/RTO, and operator approvals remain unknown.

- Preserve the reviewed APEX application export in `apex/QAFE_MIGRATION.sql` and record its SHA-256 before any import. Keep the original Forms modules and schema script unchanged; never include credentials or fixture data in exports or logs.
- Before changing the APEX application, export the current app from Builder and retain that exact artifact. To recover an application definition, import the reviewed prior export into the isolated workspace and verify the page build options, authorization schemes, and smoke-test results. Do not treat importing the app as a database rollback.
- Do not rerun `script/student-db-script.sql` to recover data. Application exports contain no database backup. If a local database restore is needed, stop testing and have the database owner restore an approved `QAFE_CLEAN` backup to an isolated target; no production or legacy restore is authorized here.
- For each approved fixture run, record the fixture marker/IDs, take read-only before/after counts, and verify cleanup in `QAFE_CLEAN`. Form 2 audit fields are checked against `CREATED_BY/DATE` and `MODIFIED_BY/DATE`; the production identity mapping from Forms `:global.user_id` remains unresolved.
- ORDS logs for this local installation are under `C:\Oracle\ORDS\logs`. Enable APEX Debug only for a bounded diagnosis, record the page/session and test case without secrets or personal data, then turn it off. Do not copy login values, session secrets, or unredacted request bodies into repository evidence.
- T033 remains open for deployment-specific backups, restore drills, audit retention, centralized logging, and recovery objectives. The local notes above do not satisfy that production gate.
